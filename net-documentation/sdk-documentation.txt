================================================================================
                    SIGNALHOUSE .NET SDK DOCUMENTATION
================================================================================

INSTALLATION
--------------------------------------------------------------------------------
  dotnet add package SignalHouseSms.Sdk

  Or add to your .csproj:
    <PackageReference Include="SignalHouseSms.Sdk" Version="1.5.1" />


INITIALIZATION
--------------------------------------------------------------------------------
  using SignalHouse.SDK;

  var client = new SignalHouseClient(
      apiKey: "your-api-token",
      baseUrl: "https://v2.signalhouse.io"
  );

  Required options:
    - apiKey   (string)  JWT token or service user token for authentication
    - baseUrl  (string)  API base URL

  The SDK throws an ArgumentException at initialization if apiKey or baseUrl
  is missing.


PER-REQUEST TOKEN OVERRIDE
--------------------------------------------------------------------------------
  Every SDK method accepts an optional RequestOptions parameter to override
  the default apiKey for that single request.

  Example:
    var response = await client.Messages.GetMessagesAsync(
        page: 1,
        limit: 10,
        options: new RequestOptions { Token = "user-specific-jwt-token" }
    );

  The per-request token takes precedence over the apiKey provided at
  initialization. The original apiKey remains unchanged.


CUSTOM HEADERS
--------------------------------------------------------------------------------
  Pass additional headers via the RequestOptions.Headers property:

  Example:
    var response = await client.Numbers.GetPhoneNumbersAsync(
        page: 1,
        limit: 20,
        options: new RequestOptions
        {
            Headers = new Dictionary<string, string>
            {
                { "X-Request-Id", "req_abc123" }
            }
        }
    );


IDEMPOTENT REQUESTS
--------------------------------------------------------------------------------
  Set RequestOptions.IdempotencyKey to make a create, update or delete safe to
  retry. The SDK sends it as the Idempotency-Key header. A retry with the same
  key and the same request replays the first response, marked with the
  response header Idempotent-Replayed: true, instead of running the request
  again.

  - Use a new key (a UUID is recommended) for each new operation, and reuse
    it only to retry that exact request.
  - Keys are scoped to the authenticated user and kept for 24 hours.
  - Reusing a key for a different request returns 422; retrying while the
    first request is still running returns 409 with Retry-After.
  - The SDK never creates a key for you. GET requests ignore it, and the
    Voice service does not support it.

  Example:
    var response = await client.Subgroups.CreateSubgroupAsync(
        new Dictionary<string, object> { { "groupId", "G0000001" }, { "subgroupName", "Support" } },
        options: new RequestOptions { IdempotencyKey = Guid.NewGuid().ToString() }
    );

AUTH  (client.Auth)
--------------------------------------------------------------------------------
  LoginAsync(string email, string password, RequestOptions? options)
    Login with email and password.

  ResetPasswordAsync(string userId, string newPassword, RequestOptions? options)
    Reset a user's password.

  GetAuthHistoryAsync(string? groupId, string? userId, int? page, int? limit,
                      RequestOptions? options)
    Get token login history.

  GetOAuthAuthorizationUrl(string provider, string? next, string? email,
                           string? linkTicket, string? reauthTicket)
    Build the URL that starts an OAuth sign-in (a browser redirect, not an
    API call). provider: "google", "microsoft", "apple", or "sso" (Enterprise
    SSO, requires email). With linkTicket (from CreateOAuthLinkAsync) it links
    the provider to the signed-in account instead of signing in; the API then
    returns the browser to /Settings/Security?pendingLink=<ticket>, which must
    be passed to ConfirmOAuthLinkAsync. With reauthTicket (from
    CreateOAuthReauthAsync) the account signs in again to confirm it's them
    ("sso" needs no email then). Query keys, only those set: email,
    linkTicket, reauthTicket, next.

  GetOAuthLinksAsync(RequestOptions? options)
    Sends a GET to /auth/oauth/links.
    Returns 200: { passwordKnown, links: [{ provider, email, linkedAt,
    lastLoginAt }] }

  CreateOAuthLinkAsync(string provider, RequestOptions? options)
    Sends a POST to /auth/oauth/:provider/link ("google", "microsoft" or
    "apple"). No request body. Requires (and spends) a fresh
    ConfirmTwoFactorIdentityAsync from the same session.
    Returns 200: { linkTicket, expiresInSeconds }
    The provider round trip returns the browser to
    /Settings/Security?pendingLink=<ticket>; pass it to ConfirmOAuthLinkAsync.

  CreateOAuthReauthAsync(string provider, RequestOptions? options)
    Sends a POST to /auth/oauth/:provider/reauth ("microsoft",
    "apple" or "sso", already linked to the account; Google is refused with 400). No request body.
    Spends nothing.
    Returns 200: { reauthTicket, reauthSecret, expiresInSeconds } (keep reauthSecret for the confirm call)
    Pass reauthTicket to GetOAuthAuthorizationUrl; the browser comes back to
    /Settings/Security with a single-use pendingReauth (the session that
    started it redeems it with ConfirmOAuthReauthAsync) or reauthError.

  ConfirmOAuthReauthAsync(string pendingReauth, string reauthSecret,
                          RequestOptions? options)
    Finish signing in again with a linked provider. Sends a POST to
    /auth/oauth/reauth/confirm with { pendingReauth, reauthSecret }. pendingReauth
    is the
    single-use value (valid 5 minutes) the CreateOAuthReauthAsync round trip returns
    to /Settings/Security with. It counts only for the same account and
    session that started it; 400 when expired or used, 403 for another
    account or session. reauthSecret is the value the create call returned;
    a wrong or missing secret is refused (403) and uses up the re-sign-in.
    Returns: { identityConfirmed } (true when 2FA is off, so it counts as a
    confirmed identity).

  ConfirmOAuthLinkAsync(string pendingLink, RequestOptions? options)
    Sends a POST to /auth/oauth/links/confirm.
    Body: { pendingLink } (required; the pendingLink query parameter from the
    /Settings/Security redirect). Links the provider only for the account the
    link was started for.
    Returns 200: the caller's { passwordKnown, links: [{ provider, email,
    linkedAt, lastLoginAt }] }

  DeleteOAuthLinkAsync(string provider, RequestOptions? options)
    Sends a DELETE to /auth/oauth/:provider/link ("google", "microsoft",
    "apple" or "sso"). Requires a fresh ConfirmTwoFactorIdentityAsync.
    400 when it is the account's only sign-in method.
    Returns 200: the remaining { passwordKnown, links }

BRANDS  (client.Brands)
--------------------------------------------------------------------------------
  GetBrandsAsync(string? id, string? subgroupId, string? groupId,
      int? page, int? limit, string? status, string? registrationType,
      RequestOptions? options, bool? currentTollFreeCarrier)
    List brands with filters.
    currentTollFreeCarrier (after options, so pass it by name): with groupId
    or subgroupId, true returns only toll-free brands that a new toll-free
    campaign in that group can use (those on the group's current toll-free
    carrier).
    Each toll-free brand carries tollFree.reviewsBusinessOnSubmit: whether
    it's reviewed when it's submitted and keeps its business details from
    then on. When that is true, the brand also carries its tollFree
    businessStructure, industry, contactEmail, contactJobTitle and
    contactJobLevel, and tollFree.rejectionReason: why it was rejected, in
    plain English, or null. On other brands these are null or absent.

  CreateBrandAsync(object brandData, RequestOptions? options)
    Create a new 10DLC brand.

  GetCallerNameAsync(string brandId, RequestOptions? options)
    Read a brand's caller name (CNAM) and the numbers it applies to:
    { brandId, companyName, cnamName, eligible, numbers: { total, items } }.
    Roles: api, admin, developer, billing, user.

  SetCallerNameAsync(string brandId, string name, RequestOptions? options)
    Set a brand's caller name for every number whose caller name comes from
    the brand, names set on a number included; later numbers get it too. The
    name may only remove characters from the brand's registered name.
    Roles: api, admin, developer.

  DeleteCallerNameAsync(string brandId, RequestOptions? options)
    Remove a brand's caller name; names set on a number are kept.
    Roles: api, admin, developer.

  CreateTollFreeBrandAsync(Dictionary<string, object> brandData,
      RequestOptions? options)
    Create a new Toll-Free brand. Sends a POST to /brand/toll-free with
    brandData as the body; registrationType is forced to TOLL_FREE.
    Toll-Free fields go under brandData["tollFree"]. tollFree.supportPhone
    must be E.164 with an optional leading "+" and no spaces, parentheses or
    hyphens (e.g. "17025550100").
    Some groups' toll-free brands are reviewed when they're submitted:
    GetTollFreeRequirementsAsync says whether a group's are. A brand in such
    a group also needs these under tollFree, where the contact is the person
    named by firstName and lastName:
      businessStructure  CO_OPERATIVE, CORPORATION,
                         LIMITED_LIABILITY_CORPORATION,
                         NON_PROFIT_CORPORATION or PARTNERSHIP
      industry           AGRICULTURE, AUTOMOTIVE, BANKING, CONSTRUCTION,
                         CONSUMER, EDUCATION, ELECTRONICS, ENGINEERING,
                         ENERGY, FAST_MOVING_CONSUMER_GOODS, FINANCIAL,
                         FINTECH, FOOD_AND_BEVERAGE, GOVERNMENT,
                         HEALTHCARE, HOSPITALITY, INSURANCE, JEWELRY,
                         LEGAL, MANUFACTURING, MEDIA, NOT_FOR_PROFIT,
                         OIL_AND_GAS, ONLINE, PROFESSIONAL_SERVICES,
                         RAW_MATERIALS, REAL_ESTATE, RELIGION, RETAIL,
                         TECHNOLOGY, TELECOMMUNICATIONS, TRANSPORTATION
                         or TRAVEL
      contactEmail       the contact's email address (a valid email, at
                         most 100 characters)
      contactJobTitle    the contact's job title (1 to 100 characters)
      contactJobLevel    the contact's job level: DIRECTOR, GM, VP, CEO,
                         CFO, GENERAL_COUNSEL or OTHER
    Its tollFree.countryCode must be "US" or "CA", and its state a 2-letter
    state or province code. In any other group, sending businessStructure,
    industry, contactEmail, contactJobTitle or contactJobLevel returns 400.
    A brand in a group whose toll-free brands are reviewed when they're
    submitted stays DCA_PENDING until it's reviewed, which usually takes 1–2
    business days. It then becomes DCA_ACTIVE if it passes, or DCA_REJECTED,
    with tollFree.rejectionReason saying why, if it doesn't. A rejected
    brand is fixed by creating the brand again with the corrections. Its
    business details can't be changed after it's submitted: companyName,
    street, city, state, postalCode, country, firstName, lastName, and
    tollFree's businessRegistrationType, taxId, countryCode,
    taxIdIssuingCountry, businessStructure, industry, contactEmail,
    contactJobTitle and contactJobLevel.
    Returns 202 with the new brand, status PENDING_CREATION. Its
    tollFree.reviewsBusinessOnSubmit says whether it's reviewed when it's
    submitted.

  GetTollFreeRequirementsAsync(string groupId, RequestOptions? options)
    Get whether a group's new toll-free brands are reviewed when they're
    submitted, which decides what they need.
    Sends a GET to /brand/toll-free-requirements/:groupId. Works for any
    group the caller can view; any other group returns 403.
    Returns 200: { groupId, reviewsBusinessOnSubmit }. When
    reviewsBusinessOnSubmit is true, a new toll-free brand needs tollFree's
    businessStructure, industry, contactEmail, contactJobTitle and
    contactJobLevel, a tollFree.countryCode of "US" or "CA", and a 2-letter
    state or province code as its state. It stays DCA_PENDING until it's
    reviewed, and its business details can't be changed after it's
    submitted. When reviewsBusinessOnSubmit is false, tollFree's
    businessStructure, industry, contactEmail, contactJobTitle and
    contactJobLevel are refused (400).

  UpdateBrandAsync(string brandId, object brandData, RequestOptions? options)
    Update brand information.

  DeleteBrandAsync(string brandId, RequestOptions? options)
    Delete (soft) a brand.

  TransferBrandAsync(string subgroupId, string[] brandIds,

  GetExternalVettingAsync(string brandId, RequestOptions? options)

  ImportExternalVettingAsync(string brandId, string vettingProviderId, string vettingId, string? vettingToken, RequestOptions? options)
    Import an existing external vetting record (not billable).

  RevetBrandAsync(string brandId, RequestOptions? options)
    Resubmit brand for vetting.

  GetAppealHistoryAsync(string brandId, RequestOptions? options)
    List identity status appeals for a brand.

  SubmitAppealAsync(string brandId, string[] appealCategories,
      string explanation, Stream? file, RequestOptions? options)
    Submit a brand identity status appeal with supporting documentation.
    Uses multipart/form-data automatically.
    appealCategories: array of strings (VERIFY_TAX_ID, VERIFY_NON_PROFIT, VERIFY_GOVERNMENT)
    explanation: string (max 1024 chars)
    file: Stream (supported: .jpg, .jpeg, .png, .bmp, .raw, .tiff, .pdf, .docx, .htm, .odt, .rtf, .txt, .xml)

  GetConsentRecordsAsync(string? groupId, string? recipientPhoneNumber,
      string? startDate, string? endDate, int? page, int? limit,
      RequestOptions? options)
    GET /message/dnc/consent-records. Export the group's consent ledger,
    newest first: one append-only record per opt-out or opt-in a recipient
    gave (a STOP or START keyword, or an opt-out link confirmation). It
    records only; sends do not read it. Required: groupId.
    recipientPhoneNumber filters to one handset (matched on its digits).
    startDate/endDate filter occurredAt: a bare date is its whole UTC day,
    a timestamp is bound as sent. limit defaults to 100, max 500.
    Returns: { data, total, page, limit }. Each record: groupId, subgroupId,
    recipientPhoneNumber, phoneNumber (the business number or RCS agent id),
    scope { type: CAMPAIGN|AGENT|SUBGROUP, id }, clearedScopes (for OPT_IN, every
    { type, id } the START cleared; empty for OPT_OUT), action (OPT_OUT|OPT_IN),
    source (KEYWORD|LINK), keyword, messageType (SMS|MMS|RCS), messageId,
    actor { type: "RECIPIENT" }, occurredAt, createdAt.

TEMPLATES  (client.Templates)
--------------------------------------------------------------------------------
  Versioned templates on /template. Every route is 404 while the API's
  RCS switch is off.

  (content: {blocks}, the only format the API stores and returns);

  API converts. A VIEW_LOCATION suggestion takes latitude/longitude or an
  address the API geocodes. Writes honor RequestOptions.IdempotencyKey.

      string? tag, RequestOptions? options)

    validation is {valid, errors, warnings}, null when the checks could not run; update returns it too, and
    publish returns {head, version, warnings}. A draft saves even when validation lists errors. On an RCS send, a
    blocked row carries blockReason, reason and issues.

      string? tag, string? search, string? sortBy,
      string? sortOrder, int? page, int? limit, RequestOptions? options)

RCS AGENTS  (client.Rcs.Agents)
--------------------------------------------------------------------------------
  RCS agents under /rcs/agent. An agent links one brand and one campaign, of
  any registration type: the campaign's numbers are its SMS fallback, and the
  brand and campaign supply the company identity and consent text for the
  carrier launch. One brand or campaign can serve many agents. An agent is a
  registration (type RCS_AGENT, agentId = registrationId "RCSA" + 10
  characters). 404 while RCS is disabled for the environment; 400 while the
  group's rcsEnabled flag is off. To use a new brand and campaign, create the
  brand (Brands.CreateBrandAsync), wait until it is VERIFIED, create the
  campaign (Campaigns.CreateCampaignAsync), then link them. agent, consent and
  defaultFallback take a Dictionary, JsonElement or JsonNode. Null arguments
  are left out of the body. Writes honor RequestOptions.IdempotencyKey.

  The agent: { agentId, groupId, subgroupId, status, registrationStatus,
  stage, brandId, brandRef, campaignId, campaignRef, links, agent, consent,
  useCase, billingCategory, defaultFallback, excludedCarriers, testers,
  contact, testerInvites, carriers, carrierUpdate, autofill, launchable, review, redlineDiff, submittedAt,
  approvedAt, history,
  createdAt, updatedAt }. launchable is true
  when the launch request would be accepted now. brandRef and
  campaignRef are the linked records' _ids; brandId and campaignId are their
  current public ids (brandId is null until TCR assigns one). links = {
  brand: { state: OK | NOT_VERIFIED | MISSING, ... }, campaign: { state: OK |
  NOT_ACTIVE | MISSING | NONE, ... } }; a deleted brand or campaign reads
  MISSING. status: DRAFT, PENDING_REVIEW, REJECTED, AGENT_CREATING (approved,
  waiting for the carrier launch), ARCHIVE_PENDING (waiting for the carrier partner
  to cancel it), ARCHIVED.

  carrierUpdate is null, or { status: REQUESTED | SENT, carriers, requestedAt,
  requestedBy, sentAt, sentBy }: the corrected launch answers the customer sent
  to Signal House after a carrier rejected a launch other carriers took (status
  PARTIALLY_LAUNCHED with a REJECTED carrier). In that state an update may
  change only consent and contact, nothing is pushed to the carrier partner, and
  RequestCarrierUpdateAsync sends the update to Signal House, which emails it to
  the carrier partner. autofill holds one marker per prefilled field, keyed by
  its path (consent.optInDetails): { source: brand | campaign | landing,
  sourceId, at, edited }. The API marks the fields it fills from the campaign or
  the brand's landing page; send autofill on create or update for the fields you
  prefilled. Omitted on update, the stored markers stay, and a marker turns
  edited once its field changes.

  CreateAsync(string brandId, string? campaignId, object? agent,
      object? consent, string? useCase, string? billingCategory,
      object? defaultFallback, List<string>? excludedCarriers,
      List<string>? testers, object? autofill, RequestOptions? options); contact is an object
      like agent
    POST /rcs/agent. Create a draft (201). brandId is a carrier brand ID,
    provisional UUID or _id; campaignId (optional until submit) is a campaign
    ID or _id of that brand. The agent's subgroup is the brand's. Blank
    consent fields fill from the campaign. Required: brandId

  ListAsync(string? groupId, string? subgroupId, string? status,
      string? brandId, string? campaignId, int? page, int? limit,
      RequestOptions? options)
    GET /rcs/agent. List agents, newest first. status is one value or a
    comma-separated list. brandId / campaignId return the agents linked to
    that brand or campaign. Returns {data, total, page, limit}.

  GetAsync(string agentId, RequestOptions? options)
    GET /rcs/agent/:agentId. One agent with the live state of its links.
    googleAgentId is Google's id for the agent, null until Google has created
    it.

  UpdateAsync(string agentId, string? brandId, string? campaignId,
      bool unlinkCampaign, object? agent, object? consent, string? useCase,
      string? billingCategory, object? defaultFallback,
      List<string>? excludedCarriers, List<string>? testers,
      bool clearUseCase, bool clearDefaultFallback, object? autofill, RequestOptions? options)
    PUT /rcs/agent/:agentId. Edit a DRAFT or REJECTED agent. agent and
    consent merge field by field; other keys replace; unlinkCampaign: true
    sends campaignId: null to unlink, and clearUseCase / clearDefaultFallback
    send useCase / defaultFallback as null. 409 once submitted.

  ValidateAsync(string agentId, RequestOptions? options)
    POST /rcs/agent/:agentId/validate. Returns {valid, errors, warnings} of
    {field, reason}; writes nothing.

  SubmitAsync(string agentId, RequestOptions? options)
    POST /rcs/agent/:agentId/submit. Create the agent at the carrier partner,
    with no review first. Needs the full profile, useCase and
    a billingCategory; otherwise 400 with details {code:
    "REGISTRATION_INCOMPLETE", errors, warnings}. The agent moves to
    AGENT_CREATING, then IN_TESTING once the partner reports it ready.
    A group that has not finished account verification gets 403 with code
    GROUP_UNVERIFIED, and a rejected group 403 with code GROUP_REJECTED; a
    pending verification passes.

  LaunchAsync(string agentId, RequestOptions? options, bool? acknowledgeFees,
      bool? acknowledgePhi)
    POST /registration/:agentId/launch. Request the launch: the launch
    requirements are checked (a VERIFIED brand, the campaign, the full consent
    with the launch video, the contact) and the agent goes to PENDING_REVIEW;
    Signal House's approval files the launch with the carrier partner. Allowed
    from IN_TESTING, REJECTED and CARRIER_REJECTED (409 otherwise); a failed
    requirement is 400 REGISTRATION_INCOMPLETE.
    The launch text must also pass the carriers' copy rules. Each failure is an
    error whose code is the carrier partner's key:
    OPT_IN_MSG_BRAND_NAME_MISSING, OPT_IN_MSG_FREQ_DISCL_MISSING,
    OPT_IN_MSG_HELP_INSTR_MISSING, OPT_IN_MSG_RATE_DISCL_MISSING,
    REG_BRAND_IN_OPT_IN_CONF_MESSAGE_MISSING, HELP_BRAND_NAME_MISSING,
    HELP_SUPP_CONTACT_MISSING, OPT_OUT_BRAND_NAME_MISSING,
    OPT_OUT_NO_CESSATION_CONF, SAMPLE_MSG_BRAND_NAME_MISSING,
    SAMPLE_RATE_DISCL_MISSING, SAMPLE_HAS_PUBLIC_URL_SHORTENER. The brand-name
    rules look for the brand's display name. 403 GROUP_UNVERIFIED and
    GROUP_REJECTED as on submit.
    When any fee is due the request needs acknowledgeFees, or it gets a 400
    with code FEE_ACKNOWLEDGEMENT_REQUIRED and nothing is held.
    The request charges the agent's launch fees: a wallet that cannot cover
    them gets a 402, and the agent stays where it is.
    The agent's launchFees quotes what the next request charges.
    When the agent's brand vertical is healthcare or insurance, the launch
    needs the protected health information (PHI) disclosure acknowledged: set
    acknowledgePhi, or the request gets a 400 REGISTRATION_INCOMPLETE whose
    errors name consent.phiAcknowledgement. The API records the
    acknowledgement as consent.phiAcknowledgement {acknowledgedAt,
    acknowledgedBy} from the caller; the client sends only the boolean, and an
    agent update cannot set it. Once recorded, a later launch request needs no
    new acknowledgement.

  RequestCarrierUpdateAsync(string agentId, RequestOptions? options)
    POST /registration/:agentId/carrier-update. Send Signal House the corrected
    launch answers after a carrier rejected a launch other carriers took; edit
    consent and contact first. Returns the agent's registration with
    data.carrierUpdate REQUESTED for the rejected carriers; it reads SENT once
    Signal House sent it. 409 when no carrier is REJECTED after a partial
    launch, or an update already waits.

  ArchiveAsync(string agentId, RequestOptions? options)
    POST /rcs/agent/:agentId/archive. Archive the agent.
    One the carrier partner created stops sending at once and stays ARCHIVE_PENDING until
    Signal House confirms the partner cancelled it, then ARCHIVED. Archiving cannot be undone;
    an agent already ARCHIVE_PENDING answers 409.

  ResendTesterInviteAsync(string agentId, string phoneNumber, RequestOptions? options)
    POST /rcs/agent/:agentId/testers/:phoneNumber/resend. Resend a tester's expired invitation.
  RemoveTesterAsync(string agentId, string phoneNumber, RequestOptions? options)
    DELETE /rcs/agent/:agentId/testers/:phoneNumber. Remove a tester at once, at any point before the agent is archived.

  CreateEntryPointsAsync(string agentId, string? body, RequestOptions? options)
    POST /rcs/agent/:agentId/entry-points. Make the links that start a chat
    with the agent: an sms: deep link in Google's format, and a short link
    that redirects to it, for a QR code. With the agent's
    defaultFallback.from, the deep link names that number, so a handset that
    cannot reach the agent texts it. body (optional, max 1,000 characters) is
    the message the chat opens with. The same request returns the same short
    link. The links reach approved testers until a carrier launches the agent.
    409 with code GOOGLE_AGENT_PENDING before Google has created the agent.
    Required: agentId
    Returns: { googleAgentId, deepLink, shortLink }

  UploadAssetAsync(string agentId, string kind, Stream file,
      string? fileName, RequestOptions? options)
    POST /rcs/agent/:agentId/asset, multipart fields kind + file. Host a logo
    (224 x 224 px, 50 KB max) or hero (1440 x 448 px, 200 KB max) PNG or
    JPEG and set it on the draft. kind: logo | hero.
    Required: agentId, kind, file


RCS MESSAGES  (client.Rcs.Messages)
--------------------------------------------------------------------------------
  Send through an agent. 404 while RCS is off for the environment, 403 while
  the group's rcsEnabled flag is off, 409 while the agent cannot send yet.

  SendAsync(string agentId, object recipients, string? templateId,
      int? templateVersion, object? content, string? contentFormat,
      string? trafficType, int? ttlSeconds, string? expireTime, object? fallback,
      string? statusCallbackUrl, bool? enableShortlink, bool? isTest,
      string? simulate, RequestOptions? options)
    POST /message/rcs.
    Send to up to 100 recipients. A blocked recipient gets a BLOCKED message and
    the rest still send. Exactly one of templateId or content; at most one of
    ttlSeconds or expireTime. contentFormat: content.v1 (default) | google.rcs.
    recipients is a list of { phoneNumber, variables, clientMessageId, metadata }.
    fallback is { mode (auto, rcs_only, sms_only), channel (auto, sms, mms), from,
    content: { text, mediaUrls }, validitySeconds }; without content the
    template's fallback, else a generated one, is used. simulate: not_capable |
    ttl_expired | delivered | read, approved testers only.
    Required: agentId, recipients
    Returns: { requested, enqueued, failed, bulkId, messages } (201)
    A recipient from 19999990000 to 19999990359 makes the whole request a
    simulation, as on SMS: it returns { simulated: true, webhooks } and nothing
    is stored, sent or charged.

  SendBatchAsync(string agentId, object recipients, ...)
    POST /message/rcs/batch. Send to up to 10,000 recipients in the
    background. Takes the same arguments as SendAsync. The request runs the
    send's request checks, splits the recipients into chunks of 100, queues
    each chunk and answers 202. Every message carries the shared bulkId;
    track progress with the messages list filtered by bulkId (GET
    /message?bulkId=) and per-message webhooks. A chunk the wallet cannot
    cover, or that is refused after acceptance, gets BLOCKED messages with
    blockReason INSUFFICIENT_FUNDS or SEND_REFUSED; a chunk that keeps
    failing gets SEND_FAILED. A retry with an idempotency key is safe (same
    bulkId, no duplicate sends); a retry without one may send duplicates.
    Required: agentId, recipients
    Returns: { bulkId, status: "ACCEPTED", recipientCount } (202)

  ValidateAsync(string agentId, object recipients, ...)
    POST /message/rcs/validate. Check a send; writes nothing. Takes the same
    arguments as SendAsync. Required: agentId, recipients
    Returns: { valid, errors, warnings, billingClass, segments,
    estimatedCostMicros, unsupportedFiles, recipients }. It runs a send's
    checks and holds no funds. valid is true only with no errors.

  EstimateAsync(string agentId, object? recipients, int? recipientCount,
      string? templateId, int? templateVersion, object? content,
      string? contentFormat, string? trafficType, int? ttlSeconds,
      string? expireTime, object? fallback, RequestOptions? options)
    POST /message/estimate with channel "rcs" added. Price a draft in
    microdollars; no charge or send. Exactly one of recipients or
    recipientCount. The fallback's from is optional for an estimate; with
    none, the fallback leg is priced on the channel of the agent's linked
    campaign. Required: agentId
    Returns: { billingClass, segments, recipientCount, rcsLeg, fallbackLeg,
    totals, balance, issues, warnings }
    rcsLeg.mediaSurcharge is the carrier's surcharge on media over 5 MB for one recipient, and rcsLeg.cost already holds it for every recipient; rcsLeg.cost is null with the fallback mode sms_only; a message over 100 MB adds a MEDIA_TOO_LARGE
    issue.

  CapabilitiesAsync(string agentId, IEnumerable<string> phoneNumbers,
      RequestOptions? options)
    POST /rcs/capabilities. Report which numbers (up to 500) can receive RCS.
    Required: agentId, phoneNumbers
    Returns: { results: [{ phoneNumber, capability, rcsEnabled, reason, features,
    carrier, checkedAt, cached }] }. capability is ENABLED, UNREACHABLE or
    UNKNOWN; reason is CAPABLE, NOT_CAPABLE, NOT_LAUNCHED_ON_CARRIER or UNKNOWN.
    rcsEnabled is true only for CAPABLE. carrier and checkedAt may be null, and
    features is empty today.

  SimulateInboundAsync(string agentId, string from, string type, string? text,
      string? postbackData, string? messageId, string? buttonId, double? latitude,

    POST /message/rcs/simulate-inbound. Fake an inbound event from an approved

    Returns: { status: "QUEUED", messageId }

  GetAsync(string messageId, RequestOptions? options)
    GET /message/:messageId. Get one message; the same route as

    carrierFeeMicros, the carrier pass-through and media surcharge it was
    charged. Required: messageId

  ListAsync(string groupId, string from, string to, string? agentId,
      string? status, int? page, int? limit, string? templateId,
      int? templateVersion, string? bulkId, string? fallbackReason,
      string? billingClass, string? deliveredChannel, bool? isTest,
      RequestOptions? options)

================================================================================
                          MULTIPART REQUESTS
================================================================================

  The following methods use multipart/form-data automatically:

    - client.Messages.SendMmsAsync(...)
    - client.Messages.SendGroupMessageAsync(...)
    - client.Landings.CreateLandingAsync(...)
    - client.Landings.UpdateLandingAsync(...)
    - client.Brands.SubmitAppealAsync(...)
    - client.Templates.UploadMediaAsync(...)

  You do not need to construct MultipartFormDataContent manually. Pass
  parameters as normal arguments and the SDK builds the form data internally.


================================================================================
                          QUERY STRING HELPERS
================================================================================

  The SDK automatically constructs query strings from method parameters.
  Any parameter with a null value is excluded, so you only need to pass
  the filters you care about.

  Example:
    // Only sends ?status=FAILED&page=1&limit=50
    var messages = await client.Messages.GetMessagesAsync(
        status: "FAILED",
        groupId: null,     // excluded
        direction: null,   // excluded
        page: 1,
        limit: 50
    );


================================================================================
                             VALIDATION
================================================================================

  The SDK validates required parameters client-side before making any HTTP
  request. If a required parameter is missing, null, or an empty string,
  the SDK throws a ValidationException immediately -- no network request
  is made.

  Validation errors have:
    - Type:    SignalHouse.SDK.Exceptions.ValidationException
    - Message: "Missing required parameter: <fieldName>"
    - Status:  400


================================================================================
                           ERROR HANDLING
================================================================================

  The SDK uses a standardized response format. Errors are NOT thrown --
  they are returned as SignalHouseResponse objects with Success = false.

  Success response:
    { Success = true, Data = { ... }, Status = 200 }

  Error response:
    { Success = false, Error = "Error message", Status = 400 }

  Error types summary:

    Source                    Behavior                           How to Handle
    -----------------------------------------------------------------------
    Missing required param    Throws ValidationException         try/catch
    HTTP 4xx/5xx from API     Returns SignalHouseResponse         Check response.Success
    Network failure           Returns SignalHouseResponse         Check response.Success


================================================================================
                       COMPLETE INTEGRATION EXAMPLE
================================================================================

  using Microsoft.AspNetCore.Mvc;
  using SignalHouse.SDK;
  using SignalHouse.SDK.Exceptions;
  using SignalHouse.SDK.Models;

  var builder = WebApplication.CreateBuilder(args);
  var app = builder.Build();

  var signalHouse = new SignalHouseClient(
      apiKey: Environment.GetEnvironmentVariable("SIGNALHOUSE_API_KEY")!,
      baseUrl: "https://v2.signalhouse.io"
  );

  // Send an SMS notification
  app.MapPost("/api/notify", async ([FromBody] NotifyRequest req) =>
  {
      try
      {
          var response = await signalHouse.Messages.SendSmsAsync(
              senderPhoneNumber: req.SenderNumber,
              recipientPhoneNumbers: new[] { req.RecipientNumber },
              messageBody: req.Message,
              statusCallbackUrl: $"{Environment.GetEnvironmentVariable("BASE_URL")}/api/delivery-status"
          );

          if (!response.Success)
          {
              return Results.Json(new { error = response.Error },
                  statusCode: response.Status ?? 500);
          }

          return Results.Json(new
          {
              messageId = response.Data?["messageId"],
              status = response.Data?["status"]
          });
      }
      catch (ValidationException ex)
      {
          return Results.BadRequest(new { error = ex.Message });
      }
      catch (Exception)
      {
          return Results.StatusCode(500);
      }
  });

  // Receive delivery status callbacks
  app.MapPost("/api/delivery-status", ([FromBody] DeliveryStatus status) =>
  {
      Console.WriteLine($"Message {status.MessageId} status: {status.Status}");
      return Results.Ok(new { received = true });
  });

  // List phone numbers with per-request token override
  app.MapGet("/api/numbers", async (HttpContext ctx, int? page, int? limit) =>
  {
      var userToken = ctx.Request.Headers.Authorization
          .ToString().Replace("Bearer ", "");

          page: page ?? 1,

      );

              statusCode: response.Status ?? 500);
      }

      return Results.Json(response.Data);
  });

  {

REGISTRATIONS AND REGIONAL REPORTING
--------------------------------------------------------------------------------
A registration is what a jurisdiction (or its provider) requires before a sender
may message. One model covers every jurisdiction: `region` is the jurisdiction
(US, GB, CA, AU; any case of "UK"/"GB"/"GBR"/"United Kingdom" is accepted for GB) and `type` selects the shape of `data`.
Types: TEN_DLC_BRAND, TEN_DLC_CAMPAIGN, TOLL_FREE_BRAND, TOLL_FREE_CAMPAIGN,
SHORT_CODE_BRAND, SHORT_CODE_PROGRAM, SHORT_CODE_LEASE (not available), VIRTUAL_LONG_CODE (UK) and ALPHANUMERIC_SENDER_ID (UK). Kinds: identity, program, sender. Channels: tenDLC, tollFree,
shortCode, virtualLongCode, alphanumeric.

Start with the catalog. GET /registration/catalog?region= returns {region,
jurisdiction, sendingRequiresRegistration, registeredThrough, provisioning, types:[{type, kind,
channel, provider, bundles, quantity:{min,max}, requiresParent, available}]}.
registeredThrough is "registration" (use this API), "brandsAndCampaigns" (the US:
register through the Brands and Campaigns APIs) or null (nothing to register, e.g.
Canada). An unlisted country requires registration and offers no types.
Quote and submit only a type whose `available` is true; other types answer 400.

GET /registration/quotes?region=&type=&quantity= (1-100, default 1) returns
{data:[quotes]}, one quote per capability bundle: {capabilities, quantity,
currency, setupAmount, monthlyAmount, totalSetupAmount, totalMonthlyAmount,
etaDays}. Amounts are integer microdollars; setupAmount/monthlyAmount are per
sender and the totals cover the quantity. groupId is optional and staff-only.

Submit on POST /registration (201) with region, type, subgroupId,
capabilities (one of the type's bundles) and data. Set RequestOptions.IdempotencyKey to make a
retry safe (see IDEMPOTENT REQUESTS). Worked example, UK Virtual Long Code: type "VIRTUAL_LONG_CODE",
capabilities ["SMS"] or ["SMS","VOICE"], data {quantity (1-100), useCases (1-10
strings), voice?}. The voice dossier is required exactly when capabilities
include VOICE: companyName, companyPhone, companyWebsite, companyEmail,
address {line1,line2?,city,postalCode,country}, companyDescription,
campaignName, campaignDescription, optInMethods (WEB|KEYWORD|VERBAL),
optOutKeywords (STOP and UNSUBSCRIBE), callTypes (LANDLINE|LOCAL|INTERNATIONAL),
callsPerDay (1-5), callDurationMinutes (1-10, 15, 30, 45 or 60) and termsUrl.

Worked example, UK alphanumeric sender ID: region "GB", type
"ALPHANUMERIC_SENDER_ID", capabilities ["SMS"], data {requestedSenderId (3-11
letters, digits, spaces, dots or dashes; at least one letter), trafficOrigin
(LOCAL: headquartered in the UK | INTERNATIONAL), trafficType (TRANSACTIONAL |
PROMOTIONAL), companyName, companyCountry, companyWebsite (http/https), industry,
messageExample, senderRelationship? (required when requestedSenderId differs from
companyName)}. quantity is always 1; the quote is one ["SMS"] bundle, 6000000
setup and 6000000 monthly by default. Once the registration is APPROVED,
data.phoneNumbers holds the granted sender (e.g. ["ACME"]); pass it as the sender
to send SMS to UK recipients. The server appends "\nOpt out: sihou.io/o/{code}"
to every message from it, counted in segments and in the estimate.

GET /registration accepts groupId, subgroupId, region, type, kind, status,
parentRegistrationId, phoneNumber (filter to registrations holding this phone
number), brandId, campaignId (RCS agents linked to that brand or
campaign), sortBy (createdAt (default), subgroupId, registrationId, region or
status), sortOrder (asc or desc (default)), page and limit (max 100) and returns
{data,totalCount,page,limit}.
Region and status each take one value or a comma-separated list (e.g.
status: "PENDING_PROVIDER,APPROVED").
In GetRegistrationsAsync, brandId and campaignId come after options, so earlier
positional calls keep their meaning; pass them by name (brandId: "B1A2C3D").
GET /registration/:registrationId returns
{registrationId, groupId, subgroupId, region, type, kind, channel, provider,
externalId, parentRegistrationId, status, stage, capabilities, submittedAt,
approvedAt, expiresAt, review:{decision,reviewedAt,reason}, data:{...type
fields}, history:[{status,stage,actor,actorType,timestamp,reason}], createdAt,
updatedAt}. For VIRTUAL_LONG_CODE, data also carries phoneNumbers, the numbers
allocated so far. Statuses: DRAFT, SIGNAL_HOUSE_REVIEW, SIGNAL_HOUSE_APPROVED,
SIGNAL_HOUSE_REJECTED, SUBMITTING, PENDING_PROVIDER, NEEDS_INFORMATION,
PAYMENT_REQUIRED (the setup fee could not be funded; retried hourly), APPROVED,
REJECTED, CANCELLED, PENDING_DELETE, DELETED, EXPIRED, RECONCILIATION_REQUIRED.
`stage` is the provider's step inside a status. Never send from a sender whose
registration is not APPROVED.

DELETE /registration/:registrationId cancels a registration (roles api, admin,
developer, user). Allowed from SIGNAL_HOUSE_REVIEW, SIGNAL_HOUSE_APPROVED,
PENDING_PROVIDER, NEEDS_INFORMATION, PAYMENT_REQUIRED and APPROVED (409
otherwise); a type that keeps drafts (RCS_AGENT) can also be cancelled from
DRAFT and SIGNAL_HOUSE_REJECTED. Numbers already allocated stay on the account
and stop sending.

UpdateRegistrationAsync(registrationId, data) sends PUT
/registration/:registrationId with data as the body to edit a DRAFT or
SIGNAL_HOUSE_REJECTED registration of a type that keeps drafts (409
otherwise). ValidateRegistrationAsync(registrationId) sends POST
/registration/:registrationId/validate and returns {valid, errors, warnings};
it writes nothing. SubmitRegistrationAsync(registrationId) sends POST
/registration/:registrationId/submit and moves a draft to SIGNAL_HOUSE_REVIEW,
or to SUBMITTING for a type Signal House does not review first (RCS_AGENT,
filed with the provider at once) (400 REGISTRATION_INCOMPLETE with the errors,
409 on a second submit). LaunchRegistrationAsync(registrationId, options, acknowledgeFees, acknowledgePhi) sends POST
/registration/:registrationId/launch: an RCS agent the carrier partner holds in
testing goes to SIGNAL_HOUSE_REVIEW, whose approval files the launch (409 unless
the agent is in testing, Signal House rejected an earlier request, or every
carrier refused one; 400 REGISTRATION_INCOMPLETE with the errors; a healthcare
or insurance brand needs acknowledgePhi: true, as on Rcs.Agents.LaunchAsync).

Staff only (the admin namespace exists only when the client enables admin, and
enabling it grants no server permission):
POST /:registrationId/review {action:"APPROVE"|"REJECT",reason?}; REJECT needs reason.
POST /:registrationId/corrections {reason,data} saves the type's correctable
fields (VIRTUAL_LONG_CODE: useCases, voice?) while the provider waits; owner,
quantity, bundle and provider order are fixed.
POST /:registrationId/numbers {phoneNumber} allocates a provider-owned number
through the recovery path.
POST /:registrationId/reconcile {externalId} links the provider order that was
placed after an ambiguous submission; never place a second order to retry.
GET /:registrationId/application?format=json returns {filename,contentType,base64};
decode base64 before saving the document.

Regional reporting: GET /message, /message/analytics, /message/analytics/detail,
/message/analytics/by-subgroup, /message/analytics/by-error-code, /message/dnc and
/message/dnc/analytics accept region and regionScopes; GET
/message/analytics/filter-options accepts region only. region is US, GB or CA
(any case of "UK"/"GB"/"GBR"/"United Kingdom" is accepted for GB) as a single value, a repeated parameter or a CSV.
regionScopes is a JSON array of OR-ed branches {region, channels, brandId?,
campaignId?, phoneNumber?} with channels from tenDLC, virtualLongCode, tollFree,
shortCode and p2p; [] matches nothing and omitting both keeps the existing scope.
Example:
[{"region":"US","channels":["tenDLC"],"brandId":["BUS1"]},
 {"region":"GB","channels":["virtualLongCode"],"phoneNumber":["447400123456"]}]
GET /message always accepts them, as do the analytics and DNC reads.

GetAnalyticsAsync, GetAnalyticsDetailAsync, GetAnalyticsThroughputAsync and
GetDncAnalyticsAsync accept registrationId (the last optional parameter, so pass
it by name; a single id or a comma-separated list, like campaignId): filter to
traffic attributed to these registrations. Except on GetAnalyticsThroughputAsync, which has no
phoneNumber filter, a phoneNumber filter takes precedence. GetPhoneNumbersAsync
accepts a single registrationId (also after options, pass it by name) to list
the numbers provisioned under that registration.

GetAnalyticsBySubgroupAsync, GetAnalyticsByErrorCodeAsync and GetDncRecordsAsync accept
registrationId (the last parameter, pass it by name) the same way, with the same
precedence. GetMessagesAsync accepts registrationId (after options, pass it by name): it
filters to messages attributed to those registrations, and a phoneNumber filter narrows
further. Every method returns 400 when registrationId is combined with campaignId.

GetMessagesAsync takes the RCS filters templateId, templateVersion, bulkId,
fallbackReason, billingClass, deliveredChannel and isTest as its last parameters, after
registrationId (pass them by name).

GetAnalyticsFilterOptionsAsync returns each phone number with its type (TOLL_FREE,
SHORT_CODE, ALPHANUMERIC, VIRTUAL_LONG_NUMBER, and older local-number spellings) and
country (ISO-2), null when unknown. TOLL_FREE, SHORT_CODE and ALPHANUMERIC are channels
by type; a US number of any other type is 10DLC and a non-US one is a Virtual Long Code.
It also returns Carriers, a plain array of carrier name strings.

UK sending is SMS only, from a +44 virtual long code to GB mobile recipients; MMS
and group MMS are unavailable. POST /message/estimate accepts a +44 sender
(recipients 10-15 digits) and returns region "GB", or "CA" for a Canadian sender.
A READY alphanumeric sender ID (e.g. "ACME") also sends SMS to UK recipients only;
its estimate includes the opt-out footer.
